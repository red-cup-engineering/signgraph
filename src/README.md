# SignGraph

A general graphing library whose semantic specialization organizes the assembled bilattice as a Chu space
-- points (SignCell's cells, and the things they are addressed by) against
observations (attributes, queries, indexes) under an evaluation, with Chu
morphisms (forward map, backward demand, adjointness) as the contract
between two organizations. That is its most boring reading, and it is the
brand name it uses.

A contract of data carried between parties with demand transported back is
what networking is. Pure.


## Named competitive target: LangGraph

[The original SignGraph package requirement](../data/records/requirements-records/signgraph-meets-then-beats-application-peers.json)
names **LangGraph** as the Leader-selected *meet-then-beat* target. **Oxigraph**
is a different, additional graph-database target. This named Work belongs
to SignGraph; it must not be silently relabeled a FeltOS-only or Organizing-only
requirement when a user asks about durable agent execution.

The actual LangGraph comparator is a low-level, **running stateful graph
orchestration framework**, not just an adjacency list: StateGraph state and
reducers, conditional edges and Send/Command routing, subgraphs, persistent
thread checkpoints and state history, human interrupts/resume, and event
streaming. See [LangGraph's overview](https://langchain-ai.github.io/langgraph/),
[graphs](https://langchain-ai.github.io/langgraph/reference/graphs/),
[persistence](https://langchain-ai.github.io/langgraph/concepts/durable_execution/)
and [interrupts](https://langchain-ai.github.io/langgraph/concepts/breakpoints/).
Its interrupt contract can restart a node and repeat earlier side effects;
that is a concrete comparative case, not an assertion that this package
already handles effects better.

SignGraph owns the **shared graph relations, identity, evidence-bearing topology
and graph transition/query semantics** used by the competitor-facing capability.
It must reuse SignCell for original Mark/cell admission, SignChain for witnessed
sequential/evidence composition, and SignCraft for higher-order realization.
Durable file/database/host lifecycle, external effects and office authority
belong to their original Engineering/Organizing/FeltOS/Computer Systems
suppliers. The SignGraph *market obligation* remains open until those
dependencies form a usable, source-qualified SignGraph-composed product,
tested on equal workloads and independently received. Do not move runtime
code into this pure graph layer, nor waive the customer requirement because
the graph source is pure.

The selected workloads, candidate differentiators, and explicitly unknown
parity/receiving are specified at the **existing original requirement** above,
not in a second benchmark registry. A green graph test proves one native
graph behavior; it does not prove LangGraph parity or a running customer
service.

## Feather graphs: posit graphs as charged feather readings

The original [Obsmetrologia feather-graph assay](https://github.com/lenticule-science/obsmetrologia/blob/main/docs/research/2026-10-16-relationlessness-spiral-pisot-prior-work-assay.md#relation-only-feather-graphs-candidate-derived-forks-and-first-negative-controls)
starts with **performed directed predication roles**, not a chosen vertex set.
The `./feather-graph` export implements one finite source-position **reading**
of those original predications, retaining each source occurrence and the
distinct `{ performed, side: token|claim }` positions even when their optional
Mark displays coincide. The sites in the result are induced by those original
positions.

`featherGraphOfPredications(originalOccurrences, { axialPredicate,
transversePredicate })` derives incomparable, source-reported sibling
continuations and finds their **separately supplied** transverse predications.
It returns explicit original occurrence-id sequences for each direct and
two-step route, leaving the comparison `unmeasured`: path composition does
not authorize a new source predication or assert that the two routes commute.
A branch without a reported cross-contact remains a branch-only candidate.
Fully saturated ordinal comparisons whose descendants are comparable do not
count as immediate source forks. Cyclic ancestry, duplicate occurrence IDs,
conflicting displays for one performed position and excessive finite branching
are refused.

`positGraphOfFeather(feather, posits)` retains **the same original feather
graph** and attaches independent source-reported for/against testimony to the
original predication occurrences. It retains multiple opposed tellings rather
than silently replacing one with the other. This is the finite-engineering
reading of the Leader's assertion that *posit graphs are feather graphs*:
Positing adds evidence/charge, not a competing primitive vertex-and-edge
carrier. The original SignChain FOUR adjudication and original authority to
admit that testimony remain with their existing owners. Even a JSON copy of
the readout cannot acquire in-process derivation authority.

**Source-admission boundary:** Feather is the earliest executable owner of
the performed source-position reader. Its original `featherSourceFields`
and `featherSourceArray` reject accessor-backed selectors, hidden or
decorated occurrence/Cell/position records, executable list iterators,
sparse arrays and over-budget source/posit testimony **before** creating
a fork, edge or charge. The guards return frozen **shallow source cuts**:
record snapshots or detached arrays of inspected own data slots. The Feather
reader traverses these cuts rather than continuing with a mutable caller
array; its nested position, Cell, and testimony records are separately
admitted. The original source occurrence IDs are retained. Posit testimony
now shares the existing 8,192-entry candidate budget across the **total**
number of source witness entries (both `for` and `against`, over all rows),
rather than admitting 8,192 records each with 8,192 copied witnesses.
The limit is inclusive, and exceeding it refuses before the over-budget
row is retained; it is an engineering resource bound, not a theorem that
source evidence is true or independent. This tighter source-admission
contract requires native and installed consumer tests before versioned release.
The downstream
Keratin workbench consumes these **same** guards with its own finite
resource limits, rather than maintaining another admission algorithm.
Original `test/feather-graph.test.mjs` is now selected by the package's
packed receiving inventory, Keratin test route and foundations
interoperability route. Fourteen focused checks executed the exact
source-only Feather module under V8; the actual Node 24.2+ frozen-registry
and independently installed consumer tests remain unreceived.

**Scientific frontier:** the original Articulating `Beneath` relation is a
proposition about performances, not yet a proved object-language
`SourceDirectedCell`. Source-record IDs and caller-declared predicate
selectors alone cannot close that gap. New source-warranted transverse-contact
production, cone-observer lift and route comparison remain the mathematical
obligations of [Obsmetrologia issue #79](https://github.com/lenticule-science/obsmetrologia/issues/79).
The present pure implementation is a **conditional view over caller-qualified
source acts**, not a theorem or authenticated source importer.

**Original consumer source-cut convergence:** the Keratin workbench now
uses the immutable arrays **returned** by Feather's original
`featherSourceArray` for discrete stalks, contacts, directed allowed pairs,
boundary walks, locks, observers and linear stalk, testimony and numeric
observations. Merely calling the guard and then iterating caller-owned arrays
was not a qualified source snapshot: a proxy's own descriptors could describe
one list while its later iterator/getter supplied a different list.
The original `test/keratin-graph.test.mjs` contains positive original-source
consumer checks with adversarial method/index access; the fixed
array bound, independent-source testimony and mathematical qualification
remain unchanged. Proxy descriptor traps still require a host security
boundary; this fix claims only that no post-admission raw-array read is
used for those admitted arrays. Native Node/pinned dependency/packed receiver
qualification remains mandatory.

## Keratin Graphs: hole-aware sheaf/fiber graphing

The `./keratin-graph` export is a **real finite computation and Graphviz
workbench** over the EXISTING original source-positioned `./feather-graph`
reading. It preserves directed source predication occurrences, gives each
performed position an explicitly supplied finite state stalk, and assigns
source-identified directed compatibility tables to every relation. It
calculates exact global section counts under a finite work budget, identifies
minimal incompatible contact cores, retains append-only source-labeled lock
events as monotone information exclusion, and compares caller-declared
observer scopes with globally liftable reports.

Original filled 2-cells and candidate unfilled boundary walks are **different
input families**. The existing exact `cellular2Complex` engine computes the
actual supplied complex and counterfactual single/aggregate filling probes;
no candidate hole is silently inserted as a face. A graph cycle, a candidate
unfilled boundary, a global-section obstruction, and a causally inaccessible
interior are *not equivalent*. A separate `keratinLinearSheaf` reading
delegates vector-stalk restrictions and exact rational H0/H1 to the original
`cellularSheaf` engine. Graph-sheaf H1 is not asserted to equal filled-surface
H1. `keratinLinearSheaf` now reports `cohomologyStatus: "exact"` only when
the original issued/re-admitted chart has passed the upstream exact rank
work guard. A valid over-budget exact chart retains its original `sheaf`,
source occurrences, and separately bounded numeric coboundary reader, but
returns `cohomology: null` and
`cohomologyStatus: "not-evaluated: rational rank work budget exceeded"`.
Nonexact restrictions have a distinct unevaluated status. Neither case is
a certificate that H0 or H1 vanishes.

`assessKeratinLinearObservations` is the strict **observed information → numeric
geometry** gate on that exact linear source graph. Each local numeric reading
carries separately named positive and negative witnesses and is evaluated
through the original Computer Data FOUR algebra. Unobserved stalks, source
disagreement, and any unknown/denied/contested testimony preserve their
source identities but produce **no numeric cochain or compatibility verdict**.
Only complete, unopposed readings go through the *existing*
`cochain → coboundary → apply` operations, returning source-identified edge
residuals. The pure cochain kernel's default zero-extension remains valid
mathematics, but observed input requires its explicit `{missing:'refuse'}`
mode. This consumer first checks FOUR testimony and complete source
coverage, **then** invokes that original cochain in strict mode: omitted
measurement can never become a measured zero at either layer. The results are conditional host-float
numerical geometry, not an authenticated measurement, exact gluing theorem,
material physics or derived causal horizon.

`keratinGraphToDot` renders directed source arrows separately from dotted
hole/filled-face **annotations**, retaining source record IDs and exact
analysis status. Graphviz is a standard visualization projection, never
source authorization. Run `npm run demo:keratin`, `npm run test:keratin`
and `node examples/keratin-hole-workbench.mjs --dot | dot -Tsvg > hole.svg`.
See [the Keratin Graph manual](./keratin-graph.md) and
[original engineering Work #30](https://github.com/red-cup-engineering/signgraph/issues/30).

The science-derived `Articulating.Beneath` admission bridge and causal
`ShroudIndexedKeratin` transport remain
[Obsmetrologia #79](https://github.com/lenticule-science/obsmetrologia/issues/79).
A caller's labels for source, hole or observer are **not** proofs; the
package export is not a deployed service. It also does not replace the
separate FEATHER-G numerical embedding codec PR.

## What lives here

Original Cell and triple source admission now comes from SignCell's public
`./cell` entry. Sites, relation/flow graphs and cohomology receive
`admitCellSequence` or `admitTripleSequence` without joining repeated source
positions. SignGraph still owns graph interpretation, isolated vertices,
ordered edge pairs and its 16,384-entry source budget. The older public
`sourceIncidenceCells`/`sourceIncidenceTriples` names in `./site` re-export the
same supplier functions for existing callers; they no longer contain a second
admission implementation. Malformed Cell sources now report their SignCell
refusal, while graph-specific constraints retain Graph diagnostics. Source
evidence is validated before an extensional projection forgets it; that
projection does not manufacture observed edges, witnesses or permissions.

- `semantic-graph` — one closed, NI-addressed graph over SignCell's typed
  Marks, declarations, and EAVT-addressed witnessed edges. Its queries and
  bounded continuations preserve every source witness without pretending that
  a page is a complete graph; gluing records schema obstructions without
  promoting projections to lossless states. All runtime graph operations and
  their twelve original regression cases were removed from SignCell.
  The `./graph` export now includes `findSignGraphRoute(graph, sourceReference,
  targetReference, { predicate? })`. It reuses Metrologic's shortest path over
  the **admitted** original SignCell graph, and returns one immutable structural
  route as typed nodes and per-hop arrays of original EAVT-addressed edges.
  Parallel witnesses survive intact, including contrary predicates if no
  predicate filter was selected; absent routes remain explicitly unreachable.
  A route does not assert its composed endpoint relation, evaluate a SignChain
  claim, perform SignCraft effects, grant an actor authority or checkpoint a
  running agent. Those remain separate original owners.


- `token-sheaf` — the sheaf of tellings over SignCell's token frame: the
  section at a token is what is told of it, restriction runs along
  specialization, and `inherited(frame, token)` glues the sections of the
  token's generalizations by knowledge join, holding a disagreement as a
  contested cell with each side's generalizations (the gluing obstruction).
  Claim by claim its FOUR value is SignChain's possibilizing of the
  source valuation. Heyting algebra (SignCell), fiber algebra (SignChain),
  sheaf (here): the dependencies run that way only.

  The original SignCell Valued carrier distinguishes an explicitly written
  FOUR value from the source's actually told positive and negative witness
  lanes. Inherited Cells retain both, but `contested` and the `for` /
  `against` source-token lists are computed from SignCell's own `told`
  operation (witness presence), never its `sidesOf` value projection.
  Consequently a presumed `stable` value without witnesses has no claimed
  source opposition, and an explicitly `absurd` value with opposing original
  witnesses retains its witnessed conflict. `reading` selection continues
  to use the independently legitimate FOUR value. The source conflict
  report is not an authenticated Activity, Agent or derivation under W3C
  PROV-O, nor an authorization or a proof of physical sheaf gluing.
  Existing `test/token-sheaf.test.mjs` exhaustively tests the 4×4 finite
  presence/value grid and the original paged claim consumer.
  `inheritedClaim(frame, token, predicate, object)` selects one exact claim
  through SignCell's shared `claimCoordinate`, retaining the same cells,
  both witness sides, source tokens and obstruction as the full section.
  `queryInheritedTellings(frame, selection, page)` selects optional token,
  predicate, object and FOUR reading with a bounded 1–128-row page. Missing
  claims remain absent; foreign tokens refuse. A `cellNi` selection must be a
  canonical RFC 6920 SHA-256 NI name, admitted through the original URI
  Services `isNiUri` contract: nonzero final Base64url pad bits refuse rather
  than masquerading as an absent Cell. This syntactic test neither proves the
  digest matches a source nor grants the reader access to the named Cell. Its `sourceCells` identifies
  the evidence-bearing source cut, while `snapshot` also binds the actual
  specialization predicate. A changed interpretation cannot reuse the old
  page identity. Mutable transported frames are read into an owned cut;
  cached indexes apply only to the original immutable frame contract.
  Hosts bind reader authority and source revision before exposing these
  pure queries; content identity itself does not supply either.
- `relational-value` — canonical records, sequences, scalars and bytes become
  source/revision-witnessed structural cells through `relationalValuePredications`.
  Its `edges` preserve directed structure; `attributes` preserve kind and lexical
  data. Cell nodes are qualified by the complete payload identity; `sourceRoot`
  and `nodeCoordinates` retain the original SEN coordinates. Shared spellings
  do not establish entity identity or publication rights.
  Payload admission preserves the established root Number and BigInt carriers,
  including safe integers that decode to Number. It requires complete byte
  equality with an original encoder output; it neither rewrites prior addresses
  nor equates the two historical source carriers.
  Source normalization delegates through SignCell's selected content-address
  supplier before graph construction. Record and array-index accessors and
  cyclic carriers refuse without invoking getters or overflowing a recursive
  local copier; repeated references to the same value remain valid separate
  structural occurrences. NFC text/key normalization, opaque `__proto__` keys
  and omitted `undefined` record members follow that supplier's carrier
  contract. Sparse arrays refuse. Root byte ownership preserves existing
  Buffer/Uint8Array payload identities. This is a carrier interpretation,
  not execution or authentication of arbitrary JavaScript objects or Proxies.
- `cell-graph` — `cellGraph(cells, observations)` builds the Chu
  relation of held SignCells under named, total observations
  (`{ name, evaluate(cell) }`) using metrologic's `chuSpaceOfEntries`
  and SignCell's canonical coincidence. Its `relationGraphOfCells`
  reads symmetric adjacency: it is suitable for connectivity, undirected
  Laplacians and diffusion, but **does not prove causal direction**.
  `flowNetworkOfCells` projects the existing oriented flow-network directly
  from SignCells, and `flowNetwork(section)` delegates to that reading.
  Every non-reflexive cell contributes the subject→object incidence with
  boundary ∂[a→b]=[b]−[a]. Reversing a link changes the boundary even when
  the symmetric relation graph is unchanged. Parallel cells retain
  distinct incidence edges; loops retain vertices but have zero boundary.
  No second graph type, signer, evidence authority or new execution path
  is introduced by these projections.
  `cellNavigationOfCells(cells, {focus, direction?, maxHops?, target?})`
  reads a bounded structural neighborhood and optional shortest route from
  the same original ordered Cells. Direction is `outgoing` (default),
  `incoming`, or `either`; reversed traversal never asserts a converse Cell.
  Metrologic's existing directed multigraph, distances and source-edge path
  reader own the traversal. SignGraph retains every admitted occurrence,
  including duplicate addresses, both witness lanes, written FOUR values and
  reflexive relations. The ordered source has its existing semantic ID;
  nodes carry original terms, canonical coincidence keys and local indices.
  `incidences` ties each `sourceIndex` to the original Cell/address and its
  `fromIndex`/`toIndex`. `neighborhood` records reached node indices and hop
  counts. `complete` means the entire reachable set has been explored.
  An optional route has `reached`, `unreachable`, or
  `not-reached-within-bound` status: exhausting a hop bound cannot establish
  absence. Route steps retain original `sourceIndex` and explicit
  `forward`/`reverse` traversal; they introduce no transitive claim.
  The existing 16,384-Cell source budget bounds the graph. `maxHops` permits
  0–32,767 and defaults to one fewer than the number of original terms.
  A renderer supplies its own explicit original-term-to-view-object binding
  and source-authored labels; geometry, focus, keyboard behavior and other
  presentation choices do not change the source ID or witness contents.
- `graph` — the deterministic typed directed-multigraph carrier and its
  traversal, cycle, path, merge, and text-rendering operations.
- `cellular-sheaf` — cellular sheaves on a graph (vector stalks on vertices and edges, restriction matrices on
  incidences), the coboundary δ⁰, the sheaf Laplacian L = δᵀδ, exact cohomology over ℚ (dim H⁰ = dim C⁰ − rank δ,
  dim H¹ = dim C¹ − rank δ, ranks from the data layer's `number/rational-matrix`), and the deterministic heat flow

  tolerance). It is the numeric side of Obsmetrologia's Laplacianizability (the Hodge isomorphism H• ≅ ker Δ, with the
  inner product supplied here), LawvereKernelH0 (the harmonic kernel is H⁰, the global sections, and diffusion converges

  floating-point symmetry round-off is averaged. **The original weighted-source
